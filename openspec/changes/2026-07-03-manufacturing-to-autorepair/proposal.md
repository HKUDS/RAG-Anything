# Proposal: 制造智能体 → 汽修智能助手 全量品牌重塑

**日期**: 2026-07-03  
**类型**: 品牌重塑 (Rebranding)  
**优先级**: 高  
**依赖**: 无  

## 动机

本系统主要服务**汽修专业学生**，现有"制造智能体"模块在命名、文案、预设场景上均为制造工厂语境（数控铣削、PLC、G代码），与汽修专业严重不匹配。需要将整个模块从代码标识符到用户界面进行全面重塑，使其贴合汽车维修领域。

## 范围

### 核心原则
- **功能不变** — 智能问答、代码解析、故障诊断三大能力完全保留
- **全量统一** — 代码标识符、路由、权限、API、文件名与 UI 文案全部一致
- **向后兼容** — 数据库权限迁移脚本，旧权限自动映射到新权限

### 命名映射

| 原名称 | 新名称 | 理由 |
|--------|--------|------|
| `manufacturing` | `autorepair` | 直接对应"汽修" |
| `Manufacturing` | `AutoRepair` | PascalCase 规范 |
| `MANUFACTURING` | `AUTOREPAIR` | 常量规范 |
| `mfg` | `ar` (auto repair) | 缩写保持一致 |
| 制造智能体 | 汽修智能助手 | 面向学生的助手定位 |
| 仪表板 | 诊断看板 | 汽修场景 |
| 代码解析 | 故障码解析 | G代码→OBD故障码 |
| G 代码 | OBD 故障码 | 汽车诊断标准 |
| PLC 指令表 | ECU 数据流 | 汽车电子 |

### 影响范围概览

| 层级 | 文件数 | 改动类型 |
|------|--------|----------|
| 前端页面 | 3 | 重命名文件 + 内容改写 |
| 前端组件/Hook | 2 | 重命名文件 + 内容改写 |
| 前端路由/导航 | 1 | 路由 + 权限 + 标签 |
| Python 模块 | ~25 | 重命名包 + 目录 + 类名 |
| 路由/权限 | 3 | 路由前缀 + 权限常量 |
| 数据库 | 1 迁移 | 权限字符串更新 |
| 脚本/测试 | 7 | 引用路径更新 |
| 文档 | 1 | 引用更新 |

**总计**: ~45 个文件  

## 非范围

- 不改变任何业务逻辑
- 不新增或删除功能
- 不修改知识图谱、LightRAG、认证等基础设施
- 不修改 `InMemoryGraphStore`（开发测试用）
- `scripts/migrate_3to5_roles.py` 和 `scripts/migrate_to_rbac.py` 不改（历史迁移脚本）

## 风险

| 风险 | 缓解措施 |
|------|----------|
| 部署时新旧路由并存导致 404 | 部署前确认所有引用已更新 |
| 权限迁移失败 | 迁移脚本带事务 + 回滚 |
| localStorage 中 `mfg_kb` 残留 | 前端自动迁移旧 key |
| 前端 chunk hash 变化导致缓存问题 | 正常 Vite 构建流程处理 |
