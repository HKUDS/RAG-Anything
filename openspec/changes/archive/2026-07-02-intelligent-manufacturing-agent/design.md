# Design: 智能制造专业智能体

## Context

RAG-Anything 是一个多模态 RAG 引擎，支持文档解析、向量检索、知识图谱构建。本项目将其应用于智能制造教育领域，为第六届全国智能制造应用技术技能大赛构建专业智能体。系统需要处理竞赛题目、评分标准、企业工艺文档、故障案例、教学视频等多模态数据，并提供文本问答、视频定位、代码解析、故障诊断等智能服务。

**约束条件**：
- 基于 RAG-Anything 现有核心能力，不修改核心引擎
- 需对接"天工讲堂"平台进行最终部署
- 数据涉及版权材料，需审核流程
- 工期包含行业专家论证与院校试点反馈环节

## Goals / Non-Goals

**Goals:**
- 构建赛项知识图谱，支持技能标签体系与谱系关联
- 建立多模态知识库构建流水线（文本/视频/代码/工艺文档）
- 开发智能制造领域专用智能体（问答/定位/溯源/诊断）
- 完成天工讲堂平台部署与3个月运维保障
- 通过行业专家论证与院校试点验证

**Non-Goals:**
- 不修改 RAG-Anything 核心检索引擎
- 不构建通用智能体框架——聚焦智能制造场景
- 不替换现有大赛评分系统——作为辅助教学工具
- 不支持实时视频流分析——仅处理已录制视频

## Decisions

### Decision 1: 分层架构（知识层 → 智能体层 → 应用层）

**选择**: 三层分离架构，每层通过明确定义的接口通信。

**备选方案**:
- 单体应用：开发速度快但不可扩展，放弃
- 微服务：过度设计，团队规模不支持

**理由**: 知识图谱、多模态流水线、智能体推理各有独立的演进节奏。分层架构允许独立迭代，同时复用 RAG-Anything 核心能力。符合 Software Architect 的 "Modular monolith — Small team, unclear boundaries" 模式。

### Decision 2: 知识图谱基于 RAG-Anything 现有图谱能力扩展

**选择**: 在 RAG-Anything 图存储层之上构建领域知识图谱 schema，不引入 Neo4j 等外部图数据库。

**理由**: RAG-Anything 已有实体-关系存储能力。新增独立图数据库增加运维复杂度，且知识图谱规模（赛项节点 < 1000）不需要专用图数据库。

### Decision 3: 视频片段定位使用时间戳索引 + 向量检索

**选择**: 视频预处理时提取关键帧并记录时间戳，问答时通过向量相似度定位相关片段，返回起止时间。

**理由**: RAG-Anything 已有视频帧提取能力（参考 `video-frame-extraction` spec）。在此基础上增加时间戳索引即可实现片段定位，无需引入新的视频理解模型。

### Decision 4: 智能体采用工具增强（Tool-augmented）模式

**选择**: 智能体核心使用 LLM + 工具调用架构，工具包括：知识库检索、代码解析器、故障诊断规则引擎、视频定位器。

**理由**: 单一 LLM 无法完成代码执行和精确视频定位。工具增强模式使智能体可以调用专用模块，保持 LLM 负责推理与对话，专用工具负责精确操作。

## Risks / Trade-offs

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|----------|
| 企业工艺库数据质量差 | 高 | 中 | 数据清洗流水线 + 人工抽检 |
| 视频转录准确度不足 | 中 | 中 | 使用 Whisper 模型 + 术语词典优化 |
| 天工讲堂平台 API 变更 | 低 | 高 | 抽象平台适配层，独立部署测试 |
| 版权材料合规风险 | 中 | 高 | 版权审核节点内置到流水线 |
| LLM 幻觉导致错误诊断 | 中 | 高 | 资源溯源机制 + 置信度阈值 + 人工审核 |
| 大赛赛题变更 | 低 | 中 | 知识图谱设计支持增量更新 |

**关键权衡**: 定制化 vs 通用性。本设计聚焦智能制造，部分组件（故障诊断规则、赛项 schema）不可直接复用于其他领域。这是刻意的取舍——先做深一个领域，验证模式后再抽象。
